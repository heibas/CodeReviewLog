# 代码评审报告

## 1. 总体结论

本次变更新增了一个评审报告子模块：通过 JGit 读取源码仓库 HEAD 提交元数据（`CommitMetadata` / `GitCommitMetadataReader`），并将一次完整的 AI 评审结果落盘为结构化 Markdown 文件（`ReviewReport` / `ReviewReportWriter`），同时附带两组单元测试。设计目标清晰：**将"源代码提交信息"与"CI 机器人/评审时间"解耦**，并通过不可变 record、纯静态无状态工具类保证可测试性。

整体实现质量较高，未发现阻断级缺陷。主要风险集中在：**CI 常见的 detached HEAD 场景下 `getBranch()` 语义不符预期**、以及部分边界（null 字段、文件名冲突、Markdown 链接注入）缺少防御。测试覆盖了主路径，但对"时区保留"这一核心承诺缺少断言。

**建议：可合入，建议先修复"高"级问题（detached HEAD 分支语义），中低优先级问题可合入后跟进。**

---

## 2. 问题清单

### 阻断

无。

### 高

**【高】GitCommitMetadataReader.java — `repository.getBranch()` 在 detached HEAD 下语义错误**

- 位置：`GitCommitMetadataReader.readHead()`，`repository.getBranch()` 一行。
- 问题：类注释明确说明本类的目的是"避免把 CI 机器人信息误认为源代码提交信息"，但 GitHub Actions 等 CI 检出代码时默认处于 **detached HEAD** 状态。此时 JGit 的 `getBranch()` 不会返回真实分支名（返回 null 或提交 SHA），导致报告中的"分支"字段在 CI 场景下恰恰是错误或缺失的——与本类的设计目标直接冲突。
- 影响：CI 环境下生成的报告分支信息不可信，且 `CommitMetadata.branch` 可能为 null 传入下游。
- 修复建议：detached HEAD 时明确返回 null 或标注 `"(detached)"`，并由调用方注入 CI 提供的真实分支名（`ReviewReport.branch` 字段已存在，应明确 `CommitMetadata.branch` 与 `ReviewReport.branch` 的职责分工：前者如实反映仓库状态，后者承载 CI 环境分支）。同时补充 detached HEAD 场景的单元测试。

### 中

**【中】ReviewReportWriter.java — `render()` 在"无 Java 变更"时仍展示模型信息，且空 runId/runAttempt 产生畸形行**

- 位置：`render()` 中 `tableRow(markdown, "模型", ...)` 与 `"Actions 运行"` 行。
- 问题：当 `hasJavaChanges == false` 时，状态行写"未调用模型"，但下一行仍输出 `provider / model`；若此时 provider/model 为 null，会渲染出 `"null / null"`（字符串拼接会把 null 转为 "null"，`escapeTable` 拦不住，因为它在拼接之后）。同理，`runId + " / 第 " + runAttempt + " 次"` 在两者为 null 时会渲染 `"null / 第 null 次"`。
- 影响：本地运行或未调用模型的场景下报告出现误导性/丑陋内容。
- 修复建议：拼接前先做空值归一（如 `Objects.toString(provider, "-")`），或在 `hasJavaChanges == false` 时模型行显示"未调用"。

**【中】ReviewReportWriter.java / ReviewReport.java / CommitMetadata.java — record 无入参校验，null 容忍度高**

- 位置：两个 record 的隐式构造器。
- 问题：`ReviewReport` 有 14 个字段，全部为可空；`write()` 对 `report.commit().shortSha()`、`report.reviewedAt()` 直接解引用，任何一处为 null 都会抛出难以定位的 NPE。
- 影响：调用方（CI 拼装逻辑）一处疏漏即运行期崩溃，且错误信息不含字段名。
- 修复建议：在 record 的紧凑构造器中对必填字段（`commit`、`reviewedAt`、`sourceRepository`）做 `Objects.requireNonNull`，明确可选字段契约。

### 低

**【低】ReviewReportWriter.java — 文件名冲突直接失败**

- 位置：`Files.writeString(..., StandardOpenOption.CREATE_NEW)`。
- 问题：文件名由"秒级时间 + shortSha + runId + attempt"组成，理论上唯一，但同一秒内的重试写入（如先写成功、流程重跑）会抛 `FileAlreadyExistsException`。
- 影响：极端场景下写报告失败；失败语义本身是安全的（不会覆盖旧报告），可接受。
- 修复建议：可捕获后追加随机后缀重试，或在文档中明确"不允许同参数重复写入"的契约。

**【低】ReviewReportWriter.java — `link()` 未对 URL/文本做 Markdown 转义**

- 位置：`link(String text, String url)`。
- 问题：`commitUrl`/`runUrl` 若含 `)` 或空格会破坏链接语法；text 未转义 `[`、`]`。当前 URL 由系统拼装风险低，但提交 SHA 文本来自 Git 数据。
- 影响：低概率的 Markdown 渲染破损。
- 修复建议：对 URL 做空格/括号过滤或 URL 编码。

**【低】GitCommitMetadataReaderTest.java — 缺少对"时区保留"的断言**

- 问题：`CommitMetadata` 的类注释承诺"时间与 Git 中保存的原始时区保持一致"，但测试只断言 `assertNotNull(authorTime)`，未设置非系统默认时区、也未断言 `ZoneOffset`。若未来有人把实现改成 `ZoneId.systemDefault()`，测试不会失败。
- 修复建议：通过 `setAuthor(new PersonIdent(name, email, when, tzOffsetMinutes))` 指定如 `+0530`，断言 `metadata.authorTime().getOffset()` 为 `+05:30`。

**【低】GitCommitMetadataReader.java — `abbreviate(7)` 不做唯一性校验**

- 问题：`ObjectId.abbreviate(7)` 是纯截断，未验证在仓库内无歧义（超大仓库可能碰撞）。
- 影响：极低概率的短 SHA 歧义，仅影响展示。
- 修复建议：如需严谨可用 `revWalk.getObjectReader().abbreviate(head, 7)`。

**【低】ReviewReportWriterTest.java — 密钥断言形同虚设**

- 问题：`assertFalse(content.contains("CODE_TOKEN"))` 断言的是两个从未注入的字面量字符串，无法真正验证"不泄露密钥"。
- 修复建议：改为注入模拟的密钥值（如在 `reviewContent` 中放入 `"sk-test-secret"`）再断言脱敏行为；或删除该断言避免误导。若设计上本组件就不接触密钥，可在注释中说明测试意图。

## 3. 值得肯定之处

1. **职责划分清晰**：元数据读取（JGit）、报告模型（record）、报告渲染/落盘三层分离；`ReviewReport` 注释明确"CI 信息不由报告组件自行读取"，便于本地运行和单测，这是很好的可测试性设计。
2. **fenced() 的自适应反引号围栏**是亮点：动态计算内容中最长反引号串并取 `max(3, longest+1)`，提交说明或 diff 内含 ```` ``` ```` 也不会破坏报告结构，考虑周到且有注释说明。
3. **表格转义完整**：`escapeTable` 处理了 `|`、`\r\n`、`\n`，防止用户提交信息破坏表格结构。
4. **路径安全处理**：`safeSegment` 过滤非法字符并特判 `"."`/`".."`，避免仓库名/sha 造成目录穿越。
5. **时间建模正确**：用 `OffsetDateTime` 保留 Git 原始时区，`PersonIdent.getTimeZoneOffset()`（分钟）换算 `ZoneOffset` 的实现正确；文件名统一用 UTC，目录按 UTC 年月日分层，避免时区歧义。
6. **资源管理规范**：`Repository`/`RevWalk` 均 try-with-resources；空仓库、非 Git 目录有明确异常信息。
7. **测试使用真实 Git 操作**（JGit init + commit）而非 mock，集成可信度高；写报告测试断言了完整路径、表格内容、链接 URL 和 `<details>` 折叠块的有无，覆盖面较好。

## 4. 后续建议

1. **补齐场景测试**（优先级最高）：
   - detached HEAD 下 `readHead()` 的行为（配合上面"高"级问题修复）；
   - 非默认时区提交的 `authorTime`/`commitTime` 偏移断言；
   - 空提交说明、含 ```` ``` ```` 与 `\r\n` 的提交说明渲染测试（`fenced` 已有间接覆盖，建议加显式用例）。
2. **明确字段契约**：为两个 record 增加紧凑构造器校验，并在 Javadoc 中标注可选/必填；梳理 `CommitMetadata.branch` 与 `ReviewReport.branch` 的语义边界，避免双份分支字段含义模糊。
3. **渲染兜底**：对 `provider`/`model`/`runId`/`runAttempt` 做空值归一，杜绝 `"null"` 字面量出现在报告中。
4. **可观测性**：`readHead` 与 `write` 可考虑返回/记录诊断信息（如解析到的 ref、detached 状态），便于 CI 日志排查。
5. **维护性**：`render()` 已较长，若后续报告区块继续增加，可抽出 `Section` 级私有方法（评审信息表 / 提交说明 / 变更概览 / AI 分析）分块构建，保持单方法可读。
6. **集成验证**：建议在 CI 中跑一次端到端 dry-run（真实 Actions 环境 + detached HEAD），确认报告中的分支、链接、目录结构符合预期后再推广。

+ * 从当前源码仓库读取 HEAD，避免把 CI 机器人或评审时间误认为源代码提交信息。

+public final class GitCommitMetadataReader {
+
+    private GitCommitMetadataReader() {
+    }
+
+    public static CommitMetadata readHead(File repositoryDirectory) throws IOException {
+        FileRepositoryBuilder builder = new FileRepositoryBuilder()
+                .setMustExist(true)
+                .findGitDir(repositoryDirectory);
+        if (builder.getGitDir() == null) {
+            throw new IllegalStateException("当前目录不在 Git 仓库中: " + repositoryDirectory.getAbsolutePath());
+        }
+
+        try (Repository repository = builder.build()) {
+            ObjectId head = repository.resolve("HEAD");
+            if (head == null) {
+                throw new IllegalStateException("当前 Git 仓库没有可评审的 HEAD 提交");
+            }
+            try (RevWalk revWalk = new RevWalk(repository)) {
+                RevCommit commit = revWalk.parseCommit(head);
+                return new CommitMetadata(
+                        head.name(),
+                        head.abbreviate(7).name(),
+                        repository.getBranch(),
+                        commit.getAuthorIdent().getName(),
+                        commit.getCommitterIdent().getName(),
+                        toOffsetDateTime(commit.getAuthorIdent()),
+                        toOffsetDateTime(commit.getCommitterIdent()),
+                        commit.getFullMessage()
+                );
+            }
+        }
+    }
+
+    private static OffsetDateTime toOffsetDateTime(PersonIdent ident) {
+        ZoneOffset zoneOffset = ZoneOffset.ofTotalSeconds(ident.getTimeZoneOffset() * 60);
+        return OffsetDateTime.ofInstant(ident.getWhen().toInstant(), zoneOffset);
+    }

+    private static String fenced(String content, String language) {
+        String value = content == null || content.isBlank() ? "（无）" : content;
+        int longestRun = 0;
+        int currentRun = 0;
+        for (int i = 0; i < value.length(); i++) {
+            currentRun = value.charAt(i) == '`' ? currentRun + 1 : 0;
+            longestRun = Math.max(longestRun, currentRun);
+        }
+        String fence = "`".repeat(Math.max(3, longestRun + 1));
+        return fence + language + "\n" + value + (value.endsWith("\n") ? "" : "\n") + fence + "\n";
+    }

+    }

+        String result = value == null || value.isBlank() ? "local" : value.replaceAll("[^A-Za-z0-9._-]", "_");
+        return ".".equals(result) || "..".equals(result) ? "_" : result;
+    }
